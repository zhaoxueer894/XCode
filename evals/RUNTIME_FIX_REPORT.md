# 运行时修复与开发回归：2026-11-08

程序问题已经修复。最终开发回归中，go-zero 1969 和 Express 3695 的候选修改都通过了受保护的官方独立验收。

这不等于 token 消耗问题全部消失：两次最终运行仍触发了 token 上限，最终修改可用。现在有证据证明程序不会再因已发现的执行故障拖住模型，并能在这组回归里留下正确修复；还没有证据证明普遍更省 token。

## 查到的具体原因

1. **快照不支持正常的符号链接。** Express 的 `node_modules/.bin` 含有链接，导致连 `ls`、`node --version` 都在执行前被拒绝。模型随后反复排查、尝试删除依赖链接，消耗了预算。
2. **命令丢掉了准备好的构建环境。** 原 Go 容器的 `GOPATH=/go` 没传给命令，Go 改用 `/root/go`，找不到已有模块缓存，转而访问被禁止的外网。`GOFLAGS`、`GOMAXPROCS` 也被丢掉了。
3. **模型不知道实际余额和工作进度。** 模型能继续读文件，却看不到共享 token、请求次数、剩余时间，以及“目前是否只增加了排查测试”。
4. **只保留文件名的压缩会丢失定位思路。** 第一版修复虽然控制了上下文体积，仍出现重复搜索、重复读同一段代码，最终没有生产代码修复。

第一轮报告中“Go 只排查、没修好”的解释需要补充：执行工具丢失依赖缓存配置确实是原因之一，不能全部归咎于模型。

## 实际改动

- 快照保存、恢复符号链接的链接文本，不读取外部目标内容；恢复仍受工作区根目录和排除规则约束。直接文件写入继续拒绝穿透链接。
- 命令保留 Go 缓存、并发设置和已激活的 Python 环境配置，模型 API 密钥仍不传给命令子进程。
- 每次模型请求都获得最新共享预算和剩余时间提示；提示不追加进长期历史，摘要调用不重复注入。
- 记录可观察的实现进度：生产文件修改、测试文件修改、距上次实现修改的工具调用数。连续探索而没有观察到实现修改时给出明确提醒。通过 shell 修改的内容不凭命令字符串推断，提示会要求查看实际 diff。
- 默认上下文改为 `bounded`，估算目标 6000 token。保留任务、项目要求、最近完整的工具调用和结果，以及带引用的证据、最近的未验证定位思路。完整历史仍保存，不拆开工具往返，不额外调用摘要模型。
- 改进文件编辑、命令工作目录的工具说明。旧实验未声明上下文策略时仍明确使用 `none`，不会随新默认值悄悄改变。

6000 是消息历史的估算目标，不含工具说明；不可丢失的任务或最新工具往返过大时可以超过目标。
